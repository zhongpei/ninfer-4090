# Bonsai 27B：PR #25 单向 FP8 验证（2026-10-05）

PR [#25](https://github.com/zhongpei/ninfer-4090/pull/25) 已合并为 `main@ad0b4d3`。本报告只运行新方案，旧版本与其他 KV 格式均未重测；比较基线来自 [PR #24 四种 KV 报告](bonsai-kv-4090-2026-10-05.md)及其本地原始记录。

结论：**修复 batch append 回归后，数值专项通过；性能收益混合，不能宣称整体提速。** C1 Fixed K7 短输入 decode 提高 2.12%，长输入 decode 下降 7.19%；长输入 prefill 提高 7.78%。六个深度的 PPL 相对旧 FP8 变化为 −0.06212% 至 +0.16046%，没有据此宣称无损或整体质量改善。

## 版本、问题与修复

合并前 Review 修正了 `issue_tile` lambda 的重复声明，提交为 `b7e7ce5`。合并后首次 native FP8 专项失败：两种 head geometry 的 `B=3, W=16` 用例均出现 K/V code、scale exact mismatch，attention 输出也未通过独立 oracle 门限。因此先暂停性能与 PPL，修复后再测。

根因是 PR 移除了外层逐 batch-row append 循环，但既有 full append launcher 的网格、输入偏移及 metadata 仍只处理第 0 行。修复在 `src/ops/kv_cache/append/{launch.cu,kernel.cuh}` 增加 batch 网格、逐行 K/V 与 positions 偏移、valid_columns 与 table_rows 选择，保留真正 batched launch；量化 codec 未变。

下面的全部新结果来自 `ad0b4d3` 加上述两文件修复（+43/−9），而不是未经修复的 merge commit。测试期间源码冻结，产品程序已重新链接修复后的 Ops。修复后的 native FP8 专项和既有 KV append 行为测试均退出 0；复用了同一代码状态的有效结果，没有重复运行数值专项。

## 环境与比较协议

硬件为两块 NVIDIA GeForce RTX 4090 24 GB，驱动 610.57.04，实际 NVCC 为 CUDA 12.8.61，Release、`sm_89`。生成逐次在 GPU 0 测量，PPL 在 GPU 1；同一程序仍只使用一张 GPU。硬件型号与工具链和旧报告一致。工件显式路径为 `/opt/ninfer-4090/Ternary-Bonsai-2-27B-ninfer-v3.ninfer`。

旧数字来自历史记录，未做同场 A/B；测量时段及设备状态差异仍可能影响性能比较。生成每组重复三次，报告中位数及范围；CLI prefill 以 `k tok/s` 四舍五入，不补造额外精度。

六次均完成 256 tokens，finish reason 为 output-limit，accepted/drafted 均为 223/223，acceptance 为 100%，平均 7.97 tokens/round，与旧记录一致。KV payload 仍为 258/1032 MiB。输入要求连续输出整数，属于特定合成工作负载，不能推广为普通对话吞吐或接受率。短输入 prefill 的新旧范围重叠，三次历史对比不足以确证该项小幅变化；长输入 decode 的三个新值均低于旧范围。

## 固定深度完整历史 PPL

已核对新旧实际 stream、input 和 target 范围，以及执行参数。quick 使用四个独立 stream，输入 token 数为 65305/65456/65511/64899，每个深度共评分 8192 targets。long 使用同一 261171-token 拼接 stream，每个深度评分 2048 targets。每个窗口从空状态构建 `[0,D)`，评分 `[D,D+2048)`；合计 24576 targets。

两组均显式 FP8、device 1、A8 prefill、prefill chunk 1024、score tile 1024，原生 RoPE。quick context 为 34816，long context 为 260096。PPL 越低越好；变化率相对同深度旧 FP8。
