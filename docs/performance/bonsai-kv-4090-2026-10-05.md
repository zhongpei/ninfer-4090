# Bonsai 27B：RTX 4090 四种 KV 对比（2026-10-05）

本报告比较同一 Bonsai 27B 工件上的 INT8、native-FP8、RK8V4 和 RK4V4-E8。质量指标来自完整历史 KV 的因果评分；生成吞吐来自另一组固定输入，二者分别解释。

结论：**sm89 产品默认选择 INT8**。它在四领域 8K/32K 的 NLL 最低，prefill 最快，短输入 decode 也最快；其他格式的局部收益不足以取代通用默认值。RK8V4 是减少 KV 占用且保留较接近质量/吞吐的选项；RK4V4-E8 优先用于容量受限的缓存；native-FP8 可用于长输入且解码占主导的场景。这里没有设定事后质量门限来宣称任一格式无损，也没有将单项 PPL 优势推广为全部任务更好。

## 版本与专项验收

测试版本为合并 PR [#24](https://github.com/zhongpei/ninfer-4090/pull/24) 后的 `main@62c1318`。PR 原始实现经专项测试发现两个问题，修复后才合并：

- native-FP8 的 32-byte PV 共享内存行沿用了 256-byte 行的 swizzle，造成地址重叠。修正为适合该行宽的映射。
- 单次 E4M3 表示 Q 和 PV 概率操作数不能达到原有误差门限。增加独立缩放的主项和残差项，仍使用 native E4M3 Tensor Core 运算；持久 KV 编码不变，softmax 最大值和分母仍使用 FP32。

原始实现 25/25 数值用例失败；最终版本 **25/25 通过**，没有放宽原有 FP8 门限。测试以公开 BF16 Q 和独立解码的 KV 为输入，对比独立 FP64 attention oracle，覆盖两种实际 head geometry、query width 1/7/16/17/65、分页与重排、ragged batch、CUDA Graph、长缓存、零 Q 和较宽数值范围。

长历史评分工具同步修复了比较契约：必须核对每个深度的实际 stream、输入范围和 target 范围，不能只比较 token 数量。相关 Python 测试 **9 passed**，C++ WindowPlan 聚焦检查通过；attention 测试与 `ninfer`、`ninfer-perplexity` 编译通过。旧功能仅比对源码，本次没有运行全仓库回归或查询 CI。

测量完成后的跟进提交 `8b9476e` 将 sm89 的 Engine、CLI、Serving 和 inference benchmark 从 BF16 默认统一为 INT8，其他架构保持原值。显式 KV 参数仍覆盖默认值；评分程序的 sm89 默认原本就是 INT8。benchmark 同时补齐 `rk4v4-e8` 解析与报告名称。

独立产品默认测试在修改前记录了五条默认断言失败，修改后 **1/1 通过**，覆盖公开 Engine 默认、三个产品入口的实际参数解析、显式 BF16/FP8/RK4V4-E8 及 Serving 到 Engine 的传递。CLI/benchmark 到 Engine 的直接赋值通过源码比对确认。四个产品和新测试 target 完成 **137/137 编译步骤**；没有重跑旧选项套件或 GPU 矩阵。此前测量均显式指定 KV，默认值调整不使这些证据失效。

## 环境与输入

硬件为 NVIDIA GeForce RTX 4090 24 GB，驱动 610.57.04，CUDA 12.8.61，Release 构建。生成性能在同一块 GPU 上逐次测量；质量测试分配到两块同型号 GPU，评分耗时不用于生成性能比较。

显式工件路径为 `/opt/ninfer-4090/Ternary-Bonsai-2-27B-ninfer-v3.ninfer`，公开名称 `bonsai2-27b`，架构 `Qwen3_5ForCausalLM`，含三值 `t2_g128_fp16` 权重。评分只加载 Text 资源，权重占用 7,189,829,632 bytes；生成包含推测解码资源，不能直接套用评分启动后的剩余显存。

质量协议在深度 D 从空状态构建完整前缀 `[0,D)`，随后评分 `[D,D+2048)`。所有格式使用相同实际 token 和 target 范围、A8 prefill、chunk 1024、原生 RoPE；INT8 是比较基线。PPL 越低越好，ΔPPL 是相对同一深度 INT8 的百分比变化。

- 8K/32K：固定 quick 四个独立语料流，每个深度共 8,192 个 target，覆盖英文参考、英文长文、中文参考和代码。
- 64K/128K/192K/258048：按 `wikitext-00 → pg19-00 → zhwiki-00 → ninfer-00` 顺序，用两个换行连接，源文件不重复。总计 261,171 tokens，每个深度评分 2,048 targets，最大实际输入 260,096 tokens。

拼接输入的 SHA-256 为 `5a0e9a0a34635a3159b473ababf8e8d44494db5a7fabdca2ff0e338336408f5f`。不同深度处于不同文本段，不能用跨深度 PPL 的升降证明长上下文能力；应只比较同一深度的 KV 格式。INT8 本身也是量化基线，本报告不等同于与 BF16 的无损性证明。

## C1 Fixed K7 生成性能

每个配置重复三次，表中给出中位数及最小–最大值。配置固定为 DFlash2 Fixed K7、prefill chunk 1024、greedy、零惩罚、关闭 thinking、256-token 输出预算；两种输入的实际 prompt 为 6,847 / 29,141 tokens，context/KV capacity 为 8,192 / 32,768。全部 24 次运行均完成 256 tokens，结束原因为 output limit。

输入要求连续输出整数，以稳定输出长度。这组任务 draft acceptance 为 100%、平均 7.97 tokens/round，属于特定合成工作负载，**不能当作普通对话吞吐或普遍接受率**。生成性能与上面的四领域 PPL 互为独立证据。

| prompt tokens | KV | prefill，k tok/s | decode，tok/s | KV payload |
|---:|---|---:|---:|---:|
| 6847 | INT8 | 3.22 (3.21–3.23) | 582.0 (579.7–582.4) | 264 MiB |
| 6847 | native-FP8 | 2.57 (2.56–2.57) | 560.9 (560.9–561.2) | 258 MiB |
| 6847 | RK8V4 | 3.19 (3.15–3.23) | 577.5 (574.8–577.5) | 200 MiB |
| 6847 | RK4V4-E8 | 3.19 (3.17–3.22) | 570.5 (570.3–578.2) | 136 MiB |
| 29141 | INT8 | 2.60 (2.57–2.61) | 415.7 (415.6–415.7) | 1056 MiB |
| 29141 | native-FP8 | 1.80 (1.79–1.80) | 484.1 (483.6–484.7) | 1032 MiB |
| 29141 | RK8V4 | 2.56 (2.54–2.57) | 404.7 (404.7–405.2) | 800 MiB |
| 29141 | RK4V4-E8 | 2.56 (2.54–2.57) | 405.5 (405.0–405.7) | 544 MiB |

native-FP8 在 29K prompt 的 decode 中位数提高约 16.5%，prefill 降低约 30.8%；6.8K prompt 的 decode 降低约 3.6%，prefill 降低约 20.2%。因此不能把一次长输入解码收益推广为所有生成流程收益。CLI 的 prefill 原始输出按 `k tok/s` 四舍五入，表内没有额外精度。

同容量下，RK8V4 的 KV payload 比 INT8 少 24.24%，RK4V4-E8 少 48.48%，native-FP8 少 2.27%。这些是缓存 payload 比例，不是整个模型的显存节省比例。

## 复现与证据

专项测试命令：

```bash
cmake --build build -j --target ninfer_softmax_attention_test ninfer ninfer-perplexity
./build/tests/ninfer_softmax_attention_test --native-fp8-only
/home/fofo/.local/bin/python3.11 -m pytest tests/test_kv_long_context_perplexity.py
```

默认值调整使用一个独立的产品选项专项 target，不运行旧选项测试套件：

```bash
cmake --build build -j --target ninfer_product_kv_defaults_test ninfer ninfer-serve ninfer_bench ninfer-perplexity
./build/tests/ninfer_product_kv_defaults_test
```

长历史矩阵使用以下参数；实际执行将 FP8 放 GPU 1，其余格式放 GPU 0，输入与执行策略相同：

```bash
/home/fofo/.local/bin/python3.11 -m tools.bench.run_kv_long_context_perplexity \
  --exe ./build/apps/ninfer-perplexity \
  --model /opt/ninfer-4090/Ternary-Bonsai-2-27B-ninfer-v3.ninfer \
  --text profiles/perplexity/bonsai-kv-pr24-2026-10-05/workload/concat-quick-four-domains.txt \
  --device 0 --depths 65536,131072,196608,258048 --tail 2048 \
  --dtypes int8,fp8,rk8v4,rk4v4-e8 --out profiles/perplexity/bonsai-kv-reproduce
```

本机保留专项日志于 `profiles/bench/pr24-kv-2026-10-05/`，生成命令与逐次结果于 `profiles/bench/pr24-kv-campaign-2026-10-05/cli/`，质量原始 schema-v3 报告和输入 manifest 于 `profiles/perplexity/bonsai-kv-pr24-2026-10-05/`。这些本地原始日志不随文档提交。

未验证范围包括超过原生 262144 tokens 的 YaRN 512K/658176 质量、四格式 C8 生成性能、Vision、多模型和其他硬件。四个长历史窗口不能代替全语料评分或具体业务准确率评测。
